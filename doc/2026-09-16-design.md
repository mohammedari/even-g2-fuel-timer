# Even G2 Fuel Timer design

Date: 2026-09-16

## Purpose

Even G2 Fuel Timer is a glanceable drink-ordering timer for social gatherings. It shows a beer mug, counts down the chosen interval, moves to a small unobtrusive display after five seconds, and asks the wearer to “Fuel up!” when the interval ends.

The glasses are the only interactive display. The implementation therefore prioritizes high contrast, few elements, a reliable exit gesture, and low image-transfer frequency.

## Screen layout

The 576 × 288 display is created once with three image containers and one text container.

| Container | Bounds `(x, y, w, h)` | Purpose |
|---|---:|---|
| `main-visual` | `(8, 72, 280, 144)` | Large mug and “Fuel up!” graphic |
| `main-timer` | `(304, 72, 256, 144)` | Large, horizontally emphasized remaining-minute display and completion logo |
| `compact` | `(408, 8, 160, 64)` | Small top-right mug and horizontally emphasized remaining time |
| `event-help` | `(8, 220, 560, 56)` | Help/error text and the only event-capturing container |

Inactive image containers receive a black PNG instead of rebuilding the page. This avoids layout flicker and preserves the requirement that `createStartUpPageContainer` is called only once.

The mug uses the generated transparent source asset `src/assets/beer-mug-pictogram.png`. It uses a bold outline and a small set of gray facets so it stays legible at compact size. Canvas composites four liquid/foam levels behind the glass, then encodes the result as a high-contrast grayscale PNG. The host converts it to the glasses’ 16-level monochrome-green display. Large labels and numbers are included in images because the SDK text container has no font-size control.

“Fuel up!” uses the generated transparent typography asset `src/assets/fuel-up-logotype.png` instead of a runtime font. The exact two-line lockup uses bold forward-italic lettering, angular terminals, and restrained speed-line cuts. The same asset is composited beside the mug on the main and completion screens so styling and glyph rendering remain consistent on hardware.

## States and interaction

The timer has four modes:

| Mode | Single tap | Swipe up/down | Double tap |
|---|---|---|---|
| `idle` | Start selected interval | Persist selected interval ±1 minute, clamped to 1–60 | First: ask in help area; second: exit immediately |
| `running` | Pause at the current remaining time | Do not change time; reveal the main screen for five seconds | First: ask in help area; second: exit immediately |
| `paused` | Resume | Change this run’s remaining time ±1 minute, clamped to 0–60; zero completes immediately | First: ask in help area; second: exit immediately |
| `completed` | Ignored during the three-second notification | Ignored | First: ask in help area; second: exit immediately |

The main help text is:

```text
・start/pause; ・・exit; swipe to change timer length
```

`CLICK_EVENT` has the protobuf zero value. Event routing must retain the `eventTypeOf` envelope check, handle explicit double-click and scroll values first, and never turn unrelated missing envelopes into clicks.

Real hardware can emit the same physical scroll through more than one event envelope. Identical scroll directions received within 250 ms are treated as one gesture. Idle and paused scrolls update only the timer image rather than retransmitting every visible container, keeping feedback responsive on the BLE image path.

The first double-click replaces the help text with an in-app exit confirmation. A single tap cancels it and restores the help appropriate to the current view; swipes are ignored while confirmation is active. A second double-click calls `shutDownPageContainer(0)` for immediate exit. This deliberately avoids the SDK-standard mode `1` dialog because the current Even Hub image path can remain stuck on `sendFailed` after that dialog opens, including after cancellation ([upstream issue #18](https://github.com/even-realities/everything-evenhub/issues/18)).

## Timing and display behavior

- The initial duration is 30 minutes unless a valid stored idle duration exists.
- Remaining time is displayed as whole minutes using `ceil(remainingMs / 60_000)`.
- Running time uses an absolute deadline (`Date.now() + remainingMs`) rather than decrementing a counter. Foreground re-entry recomputes the remainder from that deadline.
- Starting or resuming immediately clears the help text and changes to the compact top-right display. A running swipe may reveal the main screen for five seconds before compact mode returns.
- The main-screen mug is always a static full mug. Only the compact running screen animates, alternating every 500 ms between two fill levels: nearly full and nearly empty.
- Because an empty protobuf string may be omitted, the hidden help state is transmitted as a single blank character. On compact entry, the useful compact frame is queued before the two black main-container clears, and animation starts only after that first frame has transferred.
- Completion centers a static empty mug and “Fuel up!” as one visual group, waits for all completion images to finish transferring, keeps the completed view visible for about three seconds, then returns to `idle` with the persisted duration. The completion mug must not move vertically because the image-container boundary would clip its top edge.

## Persistence

The selected idle duration is stored under `even-g2-fuel-timer.settings.v1` as JSON:

```json
{ "minutes": 30 }
```

Only idle duration changes are persisted. Adjustments made while paused apply to the current run only. Missing, malformed, non-integer, or out-of-range data falls back to 30 minutes or is clamped to 1–60 as appropriate. Storage failures do not prevent the timer from operating.

## Rendering and failure handling

All calls to `updateImageRawData` pass through one promise queue because concurrent image transfers are unsupported. The app targets Even Hub SDK 0.0.14, which LZ4-compresses image payloads and paces the image path at 100 ms, holding burst calls for the next flush. Before PNG encoding, Canvas output is quantized to the G2's exact 16 grayscale levels to reduce payload complexity and avoid device-side gray-conversion failures. A per-container revision discards stale queued frames without causing updates for other containers to be skipped. Generated PNGs are cached by frame or displayed minute. A transient `sendFailed` result is retried once after 200 ms.

An image-generation or transfer failure is logged and changes the help text to include the SDK result code plus the double-tap exit hint. Text-update failures are logged. Normal and abnormal exit events stop countdowns, view timers, animation intervals, completion timeouts, and future queued image work before unsubscribing.

## Verification

1. Run `npm run build` and fix all strict TypeScript errors.
2. Run Vite and the simulator in separate terminals; optionally enable the simulator automation port for repeatable click, double-click, up, down, screenshot, and console checks.
3. Verify the initial 30-minute layout, persisted values, 1/60-minute boundaries, pause/resume, paused-only remainder changes, running swipe behavior, five-second compact transition, and main-screen reveal.
4. Verify exact deadline completion, the approximately three-second completion sequence, reset to the stored duration, and SDK exit confirmation.
5. Run `npm run pack`; do not commit `dist/` or the generated `.ehpk`.
6. Test on physical G2 hardware for gesture delivery, glyph support, 16-level visibility, image throughput, and animation flicker. The simulator is not authoritative for these characteristics.
